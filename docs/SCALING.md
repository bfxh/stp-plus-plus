## 25.3 为什么论文倍数不能直接搬过来（三条硬约束）

1. **只训 11.3M 参数**。Muon 的正交化作用在 LoRA 的 A/B 因子上，不是全权重矩阵；论文里的 2× 是全参预训练。二阶几何在低秩子空间里是否还成立，没人测过。
2. **1B + 短程**。AdEMAMix 的收益来自"几十万步之前"的梯度（β3=0.9999），我们 1920 步的总长度只有它记忆窗口的 1/5；Muon 的 2× 也是 compute-optimal（~20 token/参数）下的，我们是 11.8M/1B ≈ 0.012 token/参数，处在完全不同的区间。
3. **判定阈值**。旧集三 seed 极差 0.013 → 只有 **ppl 差 > 0.02** 才算真信号；单 seed 的 0.01 级差异一律当噪声。

### fp16/16F 为什么这次成了（唯一一个真赢的）

早期那次 `--fp16` A/B 是在**编译前**做的：当时 elementwise 429 ms / 41%，GEMM 500 ms / 47.8%，瓶颈是 3813 次逐元素 launch；dtype 换 16F 只作用于不到一半的墙钟，还被自定义 Function 打断的图吃掉收益。编译后局面翻转——elementwise 被 fuse 到 17.3 ms（3.5%），GEMM 变成 406 ms / 83.2%，16F 累加直接压在 83% 的骨架上。

关键在**不用自定义 Function**：整模型换 fp16 权重 + GradScaler，PyTorch 自己就向 cuBLAS 发 16F 累加，inductor 图完整、无 graph break。所以：

| | bf16（基线） | fp16/16F | 变化 |
|---|---|---|---|
| ppl | 4.004 | 4.004 | 0（CE 都是 1.387） |
| 墙钟 1920 步 | 1262 s | **1051 s** | **−16.7%（1.20×）** |
| 步时间 | 0.657 s | 0.547 s | — |

loss 逐位一致说明这 20% 不是拿精度换的。为什么只有 1.20× 而不是探针的 1.65–1.92×：还有一部分 GEMM 没走到 16F（大概率是 lm_head 与 attention 里的 fp32 路径）。下一步用 `STPP_PROFILE=1` 剖一版 fp16 的 320 步就能定位。

### Muon 为什么输（第一版结论）

1. **作用对象不对**。论文里的 2× 是对**全权重矩阵**做正交化；我们只训 LoRA 的 A/B 因子（16×2048 与 2048×16）。把低秩因子的动量正交化，等于把"该往哪个低秩方向走"的信息抹平成满秩方向——这恰好破坏了 LoRA 赖以生效的低秩结构。
2. **更新谱被强行拉平**。NS 把奇异值全部推到 1，等于对所有方向等权；而 LoRA 训练早期真正需要的是少数几个大奇异值方向。
3. **还更慢**。7 组 LoRA × 2 个矩阵 × 5 次 NS 迭代，虽然每个矩阵只有 16×2048，但 launch 数上去了，+15% 墙钟。

结论：**Muon 不是这套 LoRA 配置的解**。它在全参预训练上的 52% FLOPs 不能迁移到"只训 0.9% 参数"的场景。这条要写进负面结果，避免下次再试。

### AdEMAMix 为什么只是平局

1. **记忆窗口对不上长度**。β3=0.9999 的等效窗口约 1/(1−β3)=10,000 步；我们总共只跑 1,920 步，慢 EMA 只覆盖窗口的 19%，退化成"全历史平均梯度"。论文那 +95% 的 token 效率来自 101B token / 78 token·参数 的长程训练，我们是 0.012 token/参数。
2. **三个 state buffer 是纯开销**。m1/m2/v 三份状态 + 额外 elementwise，步时间 0.786 s（+20%），质量只在噪声内改善 0.007 —— 用 20% 算力换 0.2% ppl。
3. **同 Muon 的结论**：1B + LoRA + 短程，优化器层面的论文收益搬不过来。ICLR 2026 在 1.2B 全参上测到的也只是 ≈1.1×；我们在"只训 0.9% 参数"下连 1.1× 都没拿到。

**优化器这条线到此为止**（AdamW 保持不变），除非换全参训练。

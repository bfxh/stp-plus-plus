# 容量预算表：这张卡之后该买多少显存

> 全部系数来自本仓库实测（`docs/SCALING.md` §25–§30、`docs/CURVE.md`）。**标注「外推」的行不是实测**，是按实测比例线性推的，买入决策前应先在目标卡上复核第一行。

## 1. 实测系数（预算是从这几个数推出来的）

| 量 | 值 | 来源 |
|---|---|---|
| 每步 token 数 | 2048（bs4 × block512） | 配置 |
| 每 token CUDA 时间 | **0.294 ms**（601.9 ms/步） | §28 profile |
| 其中 GEMM | 326.7 ms/步（54%） | §28 |
| 其中非 GEMM | 275.2 ms/步（46%）：fmha 121.2、elementwise 78.2、softmax 28.1、reduce 25–42 | §28 |
| GEMM 效率 | 39.8 TFLOPS = 实测峰值 48.5 的 **82%** | §28.3 |
| FP8 GEMM（自写核） | 86.6 / 63.6 / 83.9 TFLOPS | §30.1 |
| 前向 FP8 的 ppl 代价 | **−0.004 ntp**（可忽略） | §30.3 |

## 2. 每一档显存的账（MiB）

| | 8 GB（现） | 12 GB | 16 GB | 24 GB |
|---|---|---|---|---|
| 权重 bf16（2.48 GB） | 2540 | 2540 | 2540 | 2540 |
| LoRA + 优化器（0.45 GB） | 460 | 460 | 460 | 460 |
| 上下文/workspace | 400 | 400 | 400 | 400 |
| 小计（固定） | 3200 | 3200 | 3200 | 3200 |
| 可用给激活 | **4988** | 9088 | 13184 | 21376 |
| 可跑 token（有 ckpt，2.19 MiB/tok） | **2048（=bs4×512）** | 4096（bs8×512） | 4096+ | 4096+ |
| 可跑 token（无 ckpt，5.5 MiB/tok，外推） | 900（不够，实测会分页） | 1650（bs4×512 差一点） | **4096 可行** | 4096 可行 |

结论一：**12 GB 只够把 bs 翻倍，不够去掉梯度重算；去掉重算的门槛在 16 GB。**

## 3. 每一档能拉开的开关 + 预期

| 开关 | 显存门槛 | 步时收益 | ppl 影响 | 证据等级 |
|---|---|---|---|---|
| block 256 / bs 8（token 不变，attention 的 L² 减半） | 8 GB（更省） | **实测 0.65 s/步 = 1.12×**（外推 1.23× 偏高：GEMM 那 54% 不变） | **不可比**：train 与 eval 的 block 都变 256，step0 ntp 1.7862→2.3855 | **已实测**（`runs/big/b256s8_probe`） |
| 去掉梯度重算 | **16 GB** | FLOPs ×8/6 → **1.26×** | 0（逐位等价） | 外推（8GB 上被 WDDM 分页破坏，未能取到干净数） |
| FP8 前向 + bf16 反传（需把 op 注册成 custom_op 修 graph break） | 12 GB（要同时留 bf16 权重） | GEMM 前向 1.9× → **1.15×** | **−0.004**（安全） | 实测精度 + 外推速度 |
| FP8 反传 | — | 再多 ~1.1× | **+0.076/20 步（否决）** | 实测 |
| bs 8 + block 512 | 12 GB | 每 token 仅 1.03×（GEMM 线性涨，attention 也线性涨） | 0 | 外推 |
| MTP k=2 | +1.5–2 GB | **负**（多一路 CE，+61 ms/步） | 未知（从未取到数） | 实测（显存/OOM） |
| r128 | 8 GB 可跑 | 0 | **+0.032（越喂越差）** | 实测 |
| 全量微调（去 LoRA） | **24 GB**（权重 2.48 + AdamW 10.2 + 激活 11.3 ≈ 24） | 0.5×（要更新 1.28B） | **可能真突破**：LoRA 的 r*=64 内在秩天花板被移除 | 外推（Biderman 2405.09673：r=256 才追平全参） |

## 4. 组合起来的账（同一 ppl 3.866，只换时间）

| 配置 | 步时 | 相对现在 | 需要 |
|---|---|---|---|
| 现在（8 GB，ckpt，block512，bf16） | 0.726 s | 1.00× | — |
| 8 GB + block 256/bs 8 | **0.65 s（实测）** | **1.12×** | ppl 不可比，等于换了一把尺子 |
| 12 GB + 上面 + FP8 前向 | ~0.51 s | 1.42× | custom_op 工程 |
| **16 GB + 去 ckpt + FP8 前向** | **~0.40 s** | **1.8×** | 买卡 |
| 24 GB + 全量微调 | 1.4 s（更慢） | 0.5× | 换 ppl 收益，不是时间 |

## 5. 建议

1. **block 256/bs 8 已实测：1.12×（0.726→0.65 s/步）**，但它把 train/eval 的 block 都改了，ppl 与 3.866 那套基线不再可比 —— 只在你愿意重开一把尺子时才用。
2. **16 GB 是性价比拐点**：去掉梯度重算（1.26×，零 ppl 代价）+ FP8 前向（1.15×）叠加成 1.8×，把 0.726 → 0.40 s/步，等价于把这张卡的训练吞吐翻近一倍。
3. **24 GB 的意义不在快，而在"能不能不用 LoRA"**：LoRA 的 r\*=64 是内在秩天花板（§26 已证 r128 越喂越差），全量微调是唯一能验证"那个 0.015 的天花板是不是 LoRA 造成的"的路径。若要的是 ppl 而不是步时，这一档才是答案。
4. **12 GB 不划算**：它只能翻 bs，而 bs 翻倍对每 token 时间只有 1.03×（GEMM 与 attention 都线性涨）。

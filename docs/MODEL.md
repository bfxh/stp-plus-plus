# §21 模型层：9/4 之后，"每 token 算几次、每次多宽"是唯一自由度

> 上一版（§20）讲的是 GPU 内核层，这一版只讲**模型层**：给定"单次矩阵乘法的成本有硬地板"，
> 模型该怎么设计。结论先给：**自由度只剩三个——每 token 的 matmul 次数、每次 matmul 的宽度、每 token 的信息量。**

---

## 21.1 模型层的账：FLOPs 只由 L 和 d 决定

对 Llama 式 decoder，每 token 的 FLOPs 近似：

```
C ≈ 2 · L · (4d² + 3d·d_ff)      # 4d² = QKVO，3d·d_ff = SwiGLU 的三个投影
```

以 Llama-3.2-1B 为例（L=16, d=2048, d_ff=8192）：

| 项 | 每层 MACs | 占比 |
|---|---|---|
| QKVO（4d²） | 16.8 M | 25% |
| SwiGLU（3d·d_ff） | 50.3 M | **75%** |
| 合计 | 67.1 M | 100% |

**9/4 的模型层含义**：`d²` 这一项没法靠"更聪明的乘法"变便宜（下界封死），
所以只能动三个量：**L**（层数）、**d / d_ff**（宽度）、**每 token 是否全算**。
任何"突破缩放定律"的模型层方案，必须落在这三者之一，否则就是空话。

**推论（很重要）**：MLP 占 75%，而 MLP 恰恰是最容易被结构化/低秩/裁剪的部分。
所以模型层的杠杆**不在 attention**，在 MLP。

---

## 21.2 三个模型层自由度，各自的证据与真实收益

| 自由度 | 具体做法 | 公开证据 | 我们的预期 |
|---|---|---|---|
| **① 每次多宽**（d / d_ff 的结构化） | Monarch/BTT 替 MLP；MLP 中间维裁剪；低秩分解 | BTT 同精度省 3.8× 算力，论文称"scaling law 优于稠密"；Monarch 训练 2× | **最实在**：MLP 从 8192→4096，FLOPs −37% |
| **② 每 token 几次**（不变量：层数） | 层共享（ALBERT 式）、层跳过、early-exit、MoE | MoE 同算力 ppl −10~20%；early-exit 省 20–30% 算力 | 层跳过 −25% FLOPs，ppl 大概率 +10%，**不划算** |
| **③ 每 token 的信息量**（不是模型结构） | token 选择（RHO）、数据配比、去重 | 已在 §17 量化 | 2× 量级，见 §17 |

注意②里"层共享"和"层跳过"是两件事：共享是**参数量不变、matmul 次数减半**（同一层算两次），
跳过是**参数和 matmul 都减半**（表达力也减半）。前者几乎必然掉点，后者要看出在哪。

---

## 21.3 模型层的"改定律"到底改了什么

缩放定律写成 `L(N, D) = E + A/N^α + B/D^β`。结构化矩阵族改的是**成本侧**：

```
稠密：  C ∝ L · d²
Monarch：C ∝ L · d^{1.5}
低秩 r： C ∝ L · d·r
```

也就是说，**同样 C 下能买到更大的 d**。这才是"better scaling law"的准确表述——
不是损失曲线变陡，而是"同样的算力能换到更宽的模型"。
BTT 论文敢说 scaling law 更好，依据就是这个（ViT-S/32 同精度省 3.8× 算力）。

所以模型层要回答的问题只有一个：**在 8GB / 这张卡上，把 MLP 换成结构化之后，
"同墙钟 ppl"能不能赢，赢多少。** 这个问题不需要 kernel，不需要 CUDA，只需要改模型定义。

## 21.4 我们这台机器能做的四个模型层实验（只有一个 1B checkpoint，所以只能做"减法"）

| # | 实验 | 改什么 | FLOPs 变化 | 判据 |
|---|---|---|---|---|
| **M1** | **MLP 中间维裁剪** d_ff 8192→6144→4096，短训 240 步恢复 | 模型结构 | −18% / −37% | 同墙钟 ppl；d_ff=4096 若 ppl 退化 <8%，就是净赚 |
| **M2** | **MLP 低秩**：把 down_proj 换成 rank-512 的因子（冻结其余） | 模型结构 | MLP −12% | 同 ppl 下省多少 FLOPs |
| **M3** | **层跳过**：16 层里固定跳 4 层（每 4 层跳 1） | 计算图 | −25% | ppl 退化是否 < 同算力稠密收益（预期：不划算，但要数） |
| **M4** | **深宽重分配**：12 层 + d_ff 8192→12288（同参数量） | 模型结构 | 不变 | ppl 是否更差（验证"深度比宽度值钱"） |

四个实验全是**模型定义层**改动：改 config、切 state_dict、短训，不碰 kernel。
每个 240 步、3 seed，单卡约 6 分钟/run，全部 24 个 run ≈ 2.5 小时。

**统一口径**：横轴用**实测 step time × steps**（不是理论 FLOPs），纵轴 ppl；
只有"同墙钟更低 ppl"或"同 ppl 更少墙钟"才算赢。M1/M2 若赢，再叠加 §17 的 token 选择。

| 节 | 层面 | 结论 |

| §17 | 数据层 | 配比 > 块级选择；超额损失 token 选择是待验证的真杠杆 |

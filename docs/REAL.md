# §15 真实语料验证：曲率选数据不迁移，"最易数据是负资产"却复现

§14 在 STP 的合成/多源 block 集上得到 **2.39× 等效数据倍数**（曲率最高 25% 打赢全量）。
这一节把它搬到真实自然文本上做同样的实验，回答"这个倍数能不能对外讲"。

**结论：不能直接讲。** 在 wikitext-103 上，按曲率选 25% 不但没有收益，**最高的那 25% 反而更差**
（+0.050 ppl，t=3.70）；只有"最易/最冗余数据是负资产"这一半复现了——但要用 **loss** 去找，
曲率找不到（ρ=0.164）。

---

## 15.1 协议

| 项 | 值 |
|---|---|
| 语料 | `Salesforce/wikitext`, `wikitext-103-raw-v1`（train 分片 0，原始 wiki 文本） |
| 规模 | 3,500,000 token → **6,536 个 512-token block**（3.35M） |
| 测试 | 末尾留出 **300 block**（与训练完全不重叠） |
| 训练 | 120 步 × bs 4 × 512 = **245,760 token**（与 §14 完全同预算） |
| 种子 | 82 / 23 / 37 |
| 打分 | 第 15 层，每块前 192 token，`κ = 1 − cos(Δh_t, Δh_{t+1})`；同一前向额外记录每块 CE（难度） |
| 选池 | 25%（1,634 块）；`all` = 全量不选，作为基线 |

构建脚本 `scripts/build_real_corpus.py`（parquet 直读，避免流式逐文档拉取的龟速）；
打分 `scripts/score_curvature.py --save-nll`；选数据 `scripts/run_select.py --scores ...`；
聚合 `scripts/agg_real.py` → `runs/select_real/results.txt`。

## 15.2 曲率分布（真实语料）

```
n=6536   mean=1.3790   sd=0.0183
p10=1.3567  p25=1.3669  p50=1.3786  p75=1.3907  p90=1.4024
```

对比 §14 合成集（n=15565，mean=1.4047，sd=0.0260）：真实文本的曲率**整体更低、更窄**
（cos 从 −0.40 收到 −0.38，sd 收窄 30%），说明自然文本的局部轨迹更"平"、块间差异更小——
这本身就是"选数据没有 headroom"的先兆。

## 15.3 四臂结果（曲率排序 vs 随机 vs 全量）

| 臂 | n | mean ppl | sd | Δ vs 全量 | t |
|---|---|---|---|---|---|
| full（全量 6536 块） | 3 | **13.1111** | 0.0157 | — | — |
| random 25% | 3 | 13.1056 | 0.0433 | −0.0055 | −0.22 |
| curv top 25%（弯） | 3 | 13.1613 | 0.0235 | **+0.0502** | **+3.70** |
| curv bottom 25%（直） | 3 | 13.1286 | 0.0234 | +0.0174 | +1.29 |

- **方向反了**：合成集上"弯=有用、直=负资产"（lo +20.6%），真实语料上"弯"反而更差 (+0.38%)，
  "直"只是轻微变差且不显著。
- 随机 25% 与全量几乎重合（−0.0055，ns），说明**选多少**不是问题，**按曲率选**才是问题。

## 15.4 曲率到底在测什么？——与难度的相关性

同一前向里顺手算了每块基座 CE：

```
nll mean=3.3170  sd=0.4106
pearson(curv, nll)=0.173   spearman=0.164
curv 最高 25% 块的平均 nll = 3.3917   （比全体 +0.075）
curv 最低 25% 块的平均 nll = 3.2057   （比全体 −0.111）
curv 最高 25% 与"最难 25%"的重叠 = 30.1%（随机基线 25%）
```

曲率与难度只有**弱正相关**（ρ≈0.16，解释约 3% 方差），重叠率只比随机高 5 个百分点。
即：曲率在真实文本上**几乎不是一个"难度探测器"**，它测到的更多是"局部表征的折返"这种
与"这条数据值不值得学"无关的几何噪声。这解释了 15.3 的失败——它挑出来的既不是最难的，
也不是最有信息的，而是**最不典型的**（wiki 里的列表、表格、外文、模板残留）。

## 15.5 对照：用 loss 排序，同一实验

若把排序键换成本征难度（基座 CE），同一预算下：

| 臂 | n | mean ppl | sd | Δ vs 全量 | t |
|---|---|---|---|---|---|
| loss top 25%（最难） | 3 | 13.1147 | 0.0030 | +0.0036 | 2.06 |
| loss bottom 25%（最易） | 3 | **13.1658** | 0.0389 | **+0.0547** | **2.44** |

- 训"最易 25%"比全量差 **+0.055 ppl**；训"最难 25%"与全量打平。
- 也就是说：**"丢掉最冗余的那一段数据"这条规则在真实语料上成立（−0.055 ppl ≈ −0.4%）**，
  但**曲率不是找它的合适工具**（曲率排序连这个效应都复现不出来）。

## 15.6 对 §14 的处置

| 说法 | 状态 |
|---|---|
| "曲率选数据 = 2.39× 数据效率" | **降级**：仅在 §14 的 block 分布上成立；真实自然文本上 **0×（且为负）** |
| "最平/最易 25% 是负资产" | **保留**：合成集（曲率排序，+20.6%）与真实集（loss 排序，+5.5%）都成立 |
| "曲率是通用样本价值探针" | **否证**：ρ(curv, nll)=0.16，选出来的块让 ppl 变差 |
| "几何量携带信息" | **收窄**：携带的是"非典型性"，不是"学习价值" |

可直接对外的表述：
> 在合成/多源混合的 block 分布上，用表征曲率排序能把数据效率提到约 2.4×；
> 在 wikitext-103 这类同质自然文本上该效应消失，且曲率与难度的相关性仅 0.16。
> 更稳的规则是"按 loss 丢掉最易的尾部"，在真实语料上约 −0.4% ppl（小但方向稳定）。

## 15.7 边界（写结论必须带）

1. **n=3，噪声 ±0.04 ppl**：+0.050 的效应 t=3.7 但仍在 1% 量级；跨语料不能外推。
2. **覆盖率仅 7%**：120 步只见到 480/6536 块，选数据的"上限收益"被预算压住；更长训练可能不同。
3. **单一语料/单一域**：wikitext 高度同质（英文维基），结论不能代表代码、对话、多语混合。
4. **曲率只在一个层（15）与一种池大小（25%）上测过**；层/池大小扫描未做。
5. **难度排序本身也不强**：最难 25% 只是打平，说明这个 1B 模型 + 245k token 的预算下，
   "难数据"带来的收益被噪声吃掉——真正的 hard-example mining 需要更大预算与去重。

## 15.8 下一步（若要把它做成能投的东西）

- 在**多域混合语料**（代码+对话+多语）上重做：同质语料天然没有选数据 headroom，
  异质语料才是选择器的主场。这是最可能救回 2× 的实验。
- 层扫描（8/15/24）+ 池大小（10%/50%）确认曲率的"非典型性"探测是否在某一层变成"价值"探测。
- 换成 **loss + 曲率联合键**（先用 loss 去尾，再用曲率去重），检验两者是否互补。
